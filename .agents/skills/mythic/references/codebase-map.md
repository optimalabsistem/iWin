# Codebase map

## Top-level layout

```
app/                      iOS app (SwiftUI, Metal compositor, bridges)
app/Mythic/               the app source + bundled artifacts
build/ntdll-unix/         our ntdll unix half — *_ios.c forks (most fixes live here)
build/wineserver/         wineserver-as-a-thread
build/win32u-unix/        win32u (display/compositor)
build/dxmt-ios/           DXMT (D3D11 → Metal)
build/x64-tests/          standalone test PEs (fpconf-x64.c, gen_asmconf.py)
build/crypto-unix/        gnutls/tls shims for crypt32
build/freetype-ios/       freetype for dwrite
wine/                     Wine 11.4 fork (submodule — modifiable freely)
FEX/                      FEX fork (submodule — modifiable freely)
research/dxmt/            DXMT source (submodule)
scripts/                  dev helper scripts
```

## Key Swift / ObjC / C files in `app/Mythic/`

| File | Role |
|------|------|
| `MythicApp.swift` | App entry. Registers the MetalLayer with DXMT shim (`mythic_display_set_layer`). |
| `ContentView.swift` | UI, tabs, launcher, settings, console; **also** `MetalHostView` (window-level CAMetalLayer), `MetalBackedView` (input), trackpad/joystick/keyboard input, launch flow. |
| `WineProcessBridge.m` | Bootstraps Wine: `__wine_main`, env setup, DLL symlinking, prefix seeding/repair. |
| `WineServerBridge.m` | Runs `wineserver_main` on a thread; socketpair fd injection (`WINESERVERSOCKET`). |
| `FEXBridge.mm` | FEXCore init, JIT pool, mmap hooks, ELF loader, Linux-syscall handler. |
| `JITAllocator.c` | Dual-mapped RW/RX memory, `csops` debugged check, no-footprint (private Mach API), SIGTRAP handler. |
| `StikJITHelper.swift` | StikDebug URL scheme + embedded JIT script, CS_DEBUGGED polling, pool placement. |
| `EntitlementChecker.swift` | Detects `increased-memory-limit`, `extended-virtual-addressing`, `allow-jit`, `get-task-allow`. |
| `LogStore.swift` / `RemoteLogger.swift` | UI console + remote log server (HTTP/UDP). |
| `mythic-jit.js` | The StikDebug debugger script (BRK #0xf00d protocol, signal/fault forwarding). |
| `PrefixExtractor.c` | Extracts `prefix-template.tar.gz` into the Wine prefix on first launch. |
| `IOSDisplayShim.m` | MetalLayer ↔ DXMT display shim (`mythic_display_set_layer`, present counter). |
| `Winios/Winios.m` | The `wineios.drv` implementation — display driver + `winios_*` input/pointer/key hooks called from Swift. |
| `Mythic-Bridging-Header.h` | Exposes the C/ObjC APIs to Swift. |
| `Mythic.entitlements` | allow-jit, increased-memory-limit, extended-virtual-addressing, get-task-allow. |

## The `*_ios.c` forks (build/ntdll-unix/) — where fixes live

`signal_arm64_ios.c`, `virtual_ios.c`, `thread_ios.c`, `process_ios.c`,
`env_ios.c`, `loader_ios.c`, `audio_null_ios.c`, `dwrite_freetype_ios.c`,
`server_ios.c`, `nsi_unixlib_ios.c`, plus `shims/` (e.g. `wine_ios_exit.h`,
which intercepts `_exit`/`_Exit`/`abort` to longjmp out per-thread).

Rule: **the `unix/*.c` files in the `wine` submodule are dead code** — these
`*_ios.c` forks are what actually build and link.

## Build chains

- `build/freetype-ios/build.sh`
- `build/wineserver/build.sh all`
- `build/ntdll-unix/build.sh`
- `build/win32u-unix/build.sh`
- `build/dxmt-ios/build.sh` (+ `patch_macho_ios.py`)
- app via `xcodebuild` (scheme `Mythic`)
- EC PE ntdll: `make -C dlls/ntdll` in `wine/build-arm64ec`, then strip + pad.

Nuke DerivedData when low-level libs change.

live file listing.
